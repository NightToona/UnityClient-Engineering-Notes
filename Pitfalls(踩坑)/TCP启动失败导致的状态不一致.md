# TCP启动失败导致的状态不一致

#Pitfalls  

## 场景

在实现 TcpServer 时，最初考虑：

> 如果默认 Port 被占用，是否需要自动寻找可用端口？

最终发现 Port 自动避让并不是当前工具的主要需求，转而关注启动流程中的状态一致性。

因此尝试通过 `try-catch` 捕获端口绑定异常。

---
## 发现问题

当启动失败时：
```
StartListener()
↓

TcpListener创建失败
↓

catch捕获异常
↓

结束方法
```

但是启动状态已经提前修改：
```
_running = true;
```

导致：
```
状态：
正在运行 √

实际：
服务器未启动 ×
```

出现状态不一致。

---
## 正确做法

重新开通一个交互方式用于重新重启服务端（即：使用Button重启）

但是这又有一个问题，如果多次点击，则会造成服务反复提供进而导致 TcpListener 和其余服务异常。

所以解决办法就涉及到了：**状态锁**

通过状态判断控制启动流程：
```
if(_running)
{
    return;
}
```

保证：
- 避免重复启动
- 避免重复创建 Listener
- 保持当前运行状态正确

同时在 EditorWindow 中保留手动启动入口：
```
启动失败
↓

恢复状态
↓

点击Button重新启动
```

---
## 收获

异常处理不仅需要处理错误本身，还需要考虑：

> 错误发生后，程序应该处于什么状态。
