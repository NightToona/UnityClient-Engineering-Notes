# 异步 Task 管理与任务生命周期简述

#CSharp 

## `_ = Task`是什么

前面在 [[异步 - 基础]] 部分已经提及过，一个 `async` 方法通常会返回一个 `Task` 对象，表示正在执行的异步任务。

使用其方法的方法体一般也需要是可异步执行的（就是使用者也必须带有 `async` 关键词）。

例如：
```cs
方法：
private static async Task StartListen() { await AcceptClientAsync; }

调用：
Task task = StartListen();
```

像这些场景中这类任务一般不需要长期运行，或者需要等待结果，所以需要方法体带有 `async` 关键词。

然而有的场景中，任务本身需要长期运行，并不需要等待结果。
但是标准写法中，不使用 `async` 则无法使用这些异步方法，
这时候就出现了一个很有用的写法：

例如：
```cs
static TcpServer()
{
	_ = StartListen(44571);
}

 private static async Task StartListen(int port) {  }
```

通过写成 `_ = Task` 的方式，表达开发者意图：

> 我知道这是个异步任务，但这里故意不等待它。

一般常用于：
- 后台监听服务
- 定时任务
- 长时间运行的异步循环

就像在HierarchyTool中，如果一直 `await StartListen()` 则会导致使用方法一直等待监听结束，而不会主动去结束方法。

## `async void`和`async Task`区别

从上面和基础知识我们知道了，`Task`作为一个类型，作用类似于`void/int/string`等返回类型。
所以在方法中，其实`async void`方法也是可以存在的。

> **有关于 `async void`**

但是这种用法一般只用于“无法返回`Task`的场景”，==常见于==：
- UI 事件
- Unity 事件回调

但也正是不返回`Task`类型，会导致以下==缺点==：
- 调用者不会等待
- 无法追踪任务状态
- 异常处理困难
所以普通业务中应避免使用这类方法。

> **有关于`async Task`**

而普通的异步则通常推荐使用这个。它的==优点在于==：
- 可以被等待
- 可以获取执行状态
- 异常可以通过 Task 传递
- 生命周期更容易管理

适用于：
- 网络请求
- 文件读取
- 后台任务
- 工具逻辑

## 异步任务生命周期 - 简述

`Task` 不仅表示一个异步操作，同时也拥有自己的生命周期。

一般会经历如下过程：
```mermaid
graph LR;
	a["创建(Task)"];
	b["开始执行"];
	c["遇到 await"];
	d["挂起等待"];
	e["等待完成"];
	f["恢复执行"];
	g["完成/异常/取消"];
	
	a --> b;
	b --> c;
	c --> d;
	d --> e;
	e --> f;
	f --> g;
```

其中，
- **创建**：调用异步方法，返回一个`Task`对象。
- **执行**：进入方法体，执行`await`前的代码。
- **挂起**：遇到`await`后，如果等待的异步操作未完成，则暂时挂起当前任务。
- **恢复**：等待结束后，从`await`后继续执行。
- **结束**：正常完成（Completed）、发生异常（Faulted）或主动取消（Canceled）。

需要注意的是：

**Task表示的是异步操作，并不等于一个线程。**

例如：
```cs
await _Listener.AcceptTcpClientAsync();
```

等待客户端连接期间，并不会一直占用一个线程，而是等待Socket完成I/O后，再恢复执行。

对于长期运行的后台任务（如监听服务器），通常还需要开发者主动管理生命周期，例如：
- 设置退出条件
- 主动释放资源
- 响应Editor关闭、程序集重载等事件

> [!NOTE] “挂起”的含义
> 当 `await` 等待的异步操作未完成时，当前异步方法会暂时停止后续代码执行，进入等待状态。
> 
> 这里的“挂起”并不是开启新线程等待，而是保存当前异步方法的执行状态，让线程可以继续执行其他任务（例如UI更新、数据实时变更等等）；当异步操作完成后，再恢复执行 `await` 后面的代码。

## 容易踩坑

#### 1. 直接在非异步的方法中使用异步类

正如上面所讲的`async void`和`async Task`，第二种方法只能使用在异步方法中。非异步方法中则会报错，而且无法使用`await`来确认是否挂起。

所以如果想在非异步方法中使用`async Task`，那就要确认方法是否不需要等待。符合则可使用开头所说的方法引用。

（这里不建议使用`async void`来处理这个问题）
