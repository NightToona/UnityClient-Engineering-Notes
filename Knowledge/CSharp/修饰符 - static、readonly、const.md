# static / readonly / const

#CSharp 

## 是什么

- `static`：属于类（共享一份），用于声明静态（全局共享）
- `readonly`：运行时只赋值一次
- `const`：编译期就写死的常量

---
## 1. static (静态)
### 定义

属于类，不属于“实例”，用于修饰变量或方法。
例：`class A{ public static int cout; }`

### 特点

- 所有实例共享同一份变量；
- 不需要 new 就能直接访问；
- 生命周期 ≈ 程序运行期间；

### 本质理解与坑点

这个变量不属于任何对象，只属于这个类本身。
（例如： `count` 只属于 `类A`，别的对象无法 `new`）

==坑点：==
- 容易造成“状态/全局污染”；
- 生命周期过长，导致出现残留；

---
## 2. readonly (只读)
### 定义

运行时只允许赋值一次，后续只能读取。
例：`class A{ public readonly int id = 1008; }`

### 特点

- 可以在构造函数中赋值，也能在初始化时赋值，其余条件不允许；
- 运行时决定值，之后不可修改；

### 本质理解与坑点

这个值可以在运行时决定，但决定后不能修改。

==坑点：==
- 误以为 **等同于const**（并不是）；
- 引用类型 readonly 只是引用不能变，对象内容仍可变。（即声明类作为可读变量，内部的变量仍可变更）

---
## 3. const （编译期常量）
### 定义

编译阶段就固定死的值。如：`const float PI = 3.14f;`

### 特点

- 必须初始化；
- 不能在运行时修改；
- 编译时直接替换成常量值；

### 本质理解与坑点

这个值在编译时就已经写死进代码了，想要修改只能重新编译。

==坑点：==
- 改了 const 后，其他引用项目不一定立即更新（需重新编译）；
- 不能用于运行时计算结果；

---
## 三者对比

| 类型         | 生命周期   | 可修改性   | 赋值时机     |
| ---------- | ------ | ------ | -------- |
| `static`   | 程序运行时  | ✔  可修改 | 任意       |
| `readonly` | 运行时仅一次 | ❌  不可改 | 构造函数、初始化 |
| `const`    | 编译期    | ❌  不可改 | 编译时      |

---
## 关联 Unity

**Unity 中常见用法：**
- `static` → 管理器 / 单例 / 缓存
- `readonly` → 配置参数 / 初始化依赖
- `const` → tag / layer / 固定字符串 / 常量等
