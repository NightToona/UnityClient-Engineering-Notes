# async / await 异步模型

#CSharp 

## 是什么

##### 1. `Task`

> `Task`用来表示一个未来会完成的异步操作。

它类似于同步方法中的返回值：
```cs
int GetNumber()
{
	return 10;
}

Task<int> GetNumberAsync()
{
	return Task<int>; //这里的Task<int>就是像上面的10。 
}
```

`Task<int>`表示： **未来某个时间会获得到一个 int 结果。**

##### 2. `async`

> `async` 用于声明一个支持异步方法的等待。

例如：
```cs
async Task Test() {  }
```

表示：
- 方法内部可能存在异步等待；
- 返回值会被包装为 `Task`；

##### 3. `await`

作用：类似于一个标签，用于声明等待一个 Task 完成，并在完成后才继续执行后续代码。

例如 HierarchyTool 中的：
```cs
TcpClient client = await listener.AcceptTcpClientAsync();
Debug.Log("Connected");
```

执行流程：

> 调用`AcceptTcpClientAsync()` → 返回 `Task<TcpClient>` → await 等待该方法完成 → 已连接 →恢复当前方法进度 → 执行 Debug


---
## 为什么需要它

脚本代码的运行逻辑都是每一行进行执行，但是如果这种方式放到 UI、网络请求之中就会出现问题。
在 UI 中，类似于进度条这类后台加载前台渲染的过程，如果都将其放入主线程中就会出现假死或是无法拖动等情况。网络请求也是一样，可能出现主线程占用中无法同时执行其他内容。

因此就出现了“异步”方法。
通过使用多线程，达到一个程序在同一时刻能额外执行需要同时运行的代码。

---
## Task 与 await 的关系

**Task**：

> 一件正在进行或是未来完成的事请。

**await**：

> 等待这件事完成。

例如：
```cs
①
Task task = DownloadAsync();
Console.WriteLine("继续执行");

②
Task task = await DownloadAsync();
Console.WriteLine("继续执行");
```

第一部分的结果：==DownloadAsync方法 + 打印== 同时执行，不会等待方法完成后才打印。
第二部分的结果：等待 ==DownloadAsync方法== 执行完成后才进行 ==打印==。

#### TCP 中的 async 应用

例如：`TcpClient client = await Listener.AcceptTcpClientAsync();`

含义： 等待客户端连接，如果未连接，就一直等待，直到连接成功后继续执行后续代码。

## 容易踩坑

#### 1. await Task.Delay() 不开线程，但是 Task.Run() 会丢入线程池

**Task.Run(() => {}) 的意思就是：**

> 把这个公国丢到线程池执行，开新线程，在新工作线程上完成而非主线程。

**Task.Delay 的意思是：**

> 我要等时间，当时间到了回来通知我。但并不开额外的线程运行。
#### 2. while + await 为什么不会卡死？

项目中的：
```cs
while(true)
{
	TcpClient client = await Listener.AcceptTcpClientAsync();
}
```

这里并不是一直反复循环检测连接，
而是：
- ↓  等待连接事件
- -  连接发生
- ↓  处理一次
- 继续等待下一次连接

所以意思就是，这个方法没有执行完，一直等待。直到完成后往后走，继续while循环。

这种模式常见于：
- TCP服务器
- 文件监听
- 消息系统
- 编辑器工具
