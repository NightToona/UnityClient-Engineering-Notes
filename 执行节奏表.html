第1天
下午
主线 在 Unity 项目里建 Editor/ 文件夹，新建 HierarchyExporter.cs，写 EditorWindow + MenuItem，跑起来显示一行 "Hello"。目标只有一个：窗口能打开。
第1天
晚上
支线 写 OnEnable/OnDisable 事件注册验证小场景（EventSender + EventReceiver），故意不写取消订阅，运行后 SetActive 3次，看 Console 重复触发几次。然后加上 OnDisable -= 修好它。写一句话总结你看到的现象。
第2–3天
主线 在 OnGUI() 里用 FindObjectsOfType<Transform>() 遍历，把场景里所有 GameObject 的名字列出来。卡住了就查 Unity 文档 EditorWindow 那页，不要先去看教程视频。
第4–5天
主线 改成显示路径（不只是名字），用 GetHierarchyPath() 拼出完整路径比如 /Canvas/Panel/Button。路径显示对了，这周的主线就完成了。
碎片时间
算法 1题简单数组题（LeetCode 704 二分查找 或 27 移除元素）。不超过 30 分钟，做不出来就看答案理解逻辑。
周末验收
✓EditorWindow 能打开，能显示场景里所有 GameObject 的路径
✓写过了 OnEnable/OnDisable 的验证场景，亲眼看到重复触发的 bug
✓有一句话总结："OnEnable/OnDisable 配对的原因是……"
第2周
XML 导出 + hierarchyChanged 监听
主线：一键导出 XML · 支线：GC Profiler 验证（重点漏洞）
Editor Tool 漏洞②
›
每天怎么做
第1–2天
主线 加一个"导出 XML"按钮，用 System.Xml.Linq.XDocument 把 GameObject 列表序列化成 XML 文件，存到项目目录。点按钮 → 生成文件 → 用记事本打开能看到内容，这步完成。
第3–4天
主线 加 EditorApplication.hierarchyChanged += RefreshList，在场景里增删 GameObject 时自动刷新窗口显示。注意在 OnDisable 里取消订阅（这就是上周支线的实际应用）。
第2天
晚上
支线 打开 Unity Profiler → Memory。写三段代码分别跑：① "a" + "b" + "c" 循环1000次，② new List<int>() 循环1000次，③ 访问 someObject.transform.position 循环1000次。看 GC Alloc 列，记下哪个有数值哪个是0。这个一定要亲眼看，不能只靠理解。
碎片时间
算法 1题中等（LeetCode 167 两数之和 II 或 15 三数之和），双指针思路，不会就先做简单的。
周末验收
✓点按钮能生成 XML 文件，里面有 GameObject 路径信息
✓在场景里增删物体，窗口自动刷新
✓Profiler 亲眼验证过：读属性不产生 GC，new 和字符串拼接会产生 GC
第2周结束 = Editor Tool MVP 完成
窗口能显示路径 + 能导出 XML + 自动刷新——这就是路线图里说的 P0 功能。已经是一个能展示的东西了，先 push 到 GitHub，写最简单的 README。
第3–4周
Editor Tool P1 + 剩余地基漏洞
主线：过滤/配置面板 · 支线：List vs Queue + ScriptableObject
Editor Tool P1 漏洞③④
›
主线（第3–4周）
加过滤功能：输入一个 Component 类型名，只导出带这个 Component 的节点（比如只导出有 Button 的物体）
加配置面板：导出路径可以在 EditorWindow 里配置，用 EditorPrefs 持久化，下次打开 Unity 还记得
加"复制路径"按钮：点某一行就把路径复制到剪贴板（GUIUtility.systemCopyBuffer）
支线（第3周：List vs Queue）
写两个对象池：一个用 List.RemoveAt(0)，一个用 Queue.Dequeue()，Stopwatch 各跑 10 万次，打印耗时对比。
把 Editor Tool 里的 GameObject 列表换成 Queue 存储（如果你还在用 List），感受实际使用场景的区别
支线（第4周：ScriptableObject）
写一个简单的 ScriptableObject 配表：定义 3 种"Buff"（加攻击、加防御、回血），每种用枚举 + 数值驱动，不要用继承子类
在 Editor Tool 里加一个读取 ScriptableObject 的演示（可以很简单：点按钮，在窗口里显示 Buff 数据）——把漏洞修复直接接进项目里
周末验收（第4周结束）
✓Editor Tool P1 功能完成，GitHub README 已更新
✓跑过 List vs Queue 性能对比，知道差距是多少倍
✓写过 ScriptableObject 数据驱动的 Buff，感受到和子类方案的区别
✓5个地基漏洞全部亲手验证过，每个有一句话总结
